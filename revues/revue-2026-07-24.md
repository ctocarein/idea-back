Le handler `activate_grid` fait, **directement dans le router**, tout ce que le référentiel réserve au service :

```python
@router.post("/admin/scoring/grids/{version}/activate", ...)
async def activate_grid(version, ctx=..., session=Depends(get_session)):

    grid = await repo.get_by_version(version)

    await repo.activate(grid)                   # écriture métier (grille active = état global)

    await session.commit()                      # transaction pilotée par le router

```

Trois écarts cumulés, tous sur le même handler :
- **instanciation en ligne** `ScoringRepository(session)` au lieu d'une injection `Depends(get_scoring_admin_service)` — idem `list_grids` (`:39`) ;

À noter que `ScoringService` existe déjà (`app/scoring/service.py`) mais n'expose que la construction de scores (`build_score`, `build_consensus_score`) — pas la gouvernance des grilles.

**Correction :** ajouter un `ScoringGovernanceService` (ou étendre `ScoringService`) avec `list_grids()` et `activate(version, actor_id)` réalisant *get + activate + audit + commit* de façon atomique, exposé via une fabrique `get_scoring_admin_service` ; le router se contente d'appeler le service.
