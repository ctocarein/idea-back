### Principe transverse — Secrets chargés via `config.py`, aucun secret en dur

#### 🟠 Important — Mot de passe admin par défaut en dur dans le seed de production

**`app/seed.py:37` (et usage `:48`)**

```python
ADMIN_PASSWORD = "ideaxion"  # à changer en prod via l'UI ou une variable d'env
ADMIN_EMAIL = "admin@ideaxion.dev"
...
await repo.create(
    email=ADMIN_EMAIL,
    password_hash=hash_password(ADMIN_PASSWORD),
    full_name=ADMIN_NAME,
    role=Role.ADMIN,
    status=AccountStatus.ACTIVE,
)
```

Le docstring du fichier l'annonce clairement comme un **« Seed de production minimal — compte admin »**, lancé via `make seed` / `python -m app.seed`. Le mot de passe du **seul compte administrateur** est donc :

- **écrit en dur** dans le code source, alors que tout le reste de la configuration sensible (`jwt_secret`, `smtp_password`, clés LLM, `minio_access_key`) est correctement typé `SecretStr` et chargé depuis l'environnement via `app/core/config.py` — ce fichier est **la seule exception** de tout le dépôt ;
- **publié dans un dépôt GitHub public** — la paire `admin@ideaxion.dev` / `ideaxion` est donc connue de quiconque lit le repo ;
- **trivial** (un mot du dictionnaire, 8 caractères), et poussé en base avec `status=ACTIVE`, immédiatement utilisable.

Le commentaire « à changer en prod » repose entièrement sur la vigilance de l'opérateur : rien dans le code ne **force** ni ne **vérifie** ce changement. Si le seed est joué en production et que l'étape manuelle est oubliée (scénario réaliste), la plateforme démarre avec un compte admin à identifiants publics. Atténuations réelles mais insuffisantes : le seed est **manuel** (non déclenché au démarrage — absent de `main.py`) et **idempotent** (`get_by_email` saute un email déjà présent, donc rejouer le seed ne réinitialise pas un mot de passe déjà changé).

*Correction suggérée :* charger le mot de passe depuis la configuration plutôt qu'en dur, et refuser de créer l'admin si le secret est absent, au lieu de retomber sur une valeur triviale. Par exemple :

```python
from app.core.config import get_settings

settings = get_settings()
admin_password = settings.seed_admin_password  # SecretStr | None dans config.py
if admin_password is None:
    logger.warning("seed_admin_skipped_no_password")  # pas de compte à identifiants connus
    return
await repo.create(
    email=settings.seed_admin_email,
    password_hash=hash_password(admin_password.get_secret_value()),
    ...
)
```

À défaut d'un secret fourni, une alternative acceptable est de **générer un mot de passe aléatoire** et de le journaliser une seule fois (log de premier démarrage) en imposant un changement à la première connexion. L'essentiel : **plus aucune valeur d'identifiant devinable dans le source**.
