## Constats détaillés

### Principe 3 & 4 — I/O externe faillible / coût LLM non borné

#### 🟠 IMPORTANT — `app/academy/router.py` : endpoints LLM interactifs sans `rate_limit`

Plusieurs routes appellent le LLM en synchrone dans le chemin requête (`app/academy/service.py:134` `guided_turn`, `:278/:306/:340/:383` modules/fiches/rescore), mais **aucune n'est protégée par un `rate_limit`** :

- `POST /academy/build/start`, `POST /academy/build/{id}/turn` ;
- `POST /academy/modules/start`, `POST /academy/modules/{id}/turn`, `.../prefill-form`, `.../generate-fiches`, `.../rescore`.

Le provider est bien résilient (timeout/retry/circuit breaker via `app/llm`), mais rien ne borne le **débit d'appels** : un porteur authentifié (`ACADEMY_PROGRESS`) peut enchaîner les tours et faire grimper le coût LLM sans plafond. Le contraste avec les modules frères est net et intentionnel côté eux :

- `app/studio/router.py:39` → `rate_limit("logo_generate", limit=12, window_seconds=60, fail_open=False)` ;
- `app/pitch/router.py:58` → `rate_limit("pitch_generate", limit=15, ..., fail_open=False)` ;
- `app/pitch/router.py:73` → `rate_limit("deck_generate", limit=10, ..., fail_open=False)`.

**Correction :** appliquer un `rate_limit(..., fail_open=False)` sur chaque endpoint academy déclenchant un appel LLM (au minimum `build/*/turn`, `modules/*/turn`, `prefill-form`, `generate-fiches`, `rescore`), en cohérence avec studio/pitch. `fail_open=False` est le bon choix pour un endpoint coûteux (fail-closed si Redis est indisponible).
